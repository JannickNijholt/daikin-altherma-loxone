# Finding: BRP069A78 has no usable local API (firmware 4.0.1)

Date: 2026-10-21
Devices: 2× BRP069A78 "WLAN cartridge Heating" (Daikin Altherma), firmware 4.0.1,
at 192.168.10.7 ("Klimaatregeling boven") and 192.168.10.3 ("Klimaatregeling beneden").

## Question

Can the Loxone Miniserver talk to the Daikin units directly through the existing
WLAN cartridges, without Home Assistant and without a bridge?

## What was tested (read-only)

Script: [`tools/probe_brp069a78.py`](../../tools/probe_brp069a78.py)

| Protocol / path | Result |
|---|---|
| TCP port scan (80, 443, 8080, 8443, 1883, 8883, 5683, 30050) | Only **80/tcp** open |
| HTTP `GET /` | `404 File / not_found` |
| Classic Daikin API (`/common/basic_info`, `/aircon/get_control_info`, `/aircon/get_sensor_info`) | 404 |
| Newer Daikin API `POST /dsiot/multireq` (pydaikin BRP084 protocol) | 404 |
| Altherma LAN-adapter WebSocket `ws://<ip>/mca` (BRP069A61/62 protocol) | 404, no upgrade |
| HTTP `GET /config/adapter/info` | 200, adapter identity, cloud `gatewayDeviceId`, connection status |
| HTTP `GET /config/firmware/info` | 200, `{"version":"4.0.1",...}` |
| HTTP `GET /config/wlan/info` | 200, IP + Wi-Fi status |
| HTTP `GET /config/adapter/product_info` | 200, model, serial, `device_type: heating` |
| UDP 30050 `DAIKIN_UDP/common/basic_info` | `ret=OK,model=BRP069A78,mac=…` (discovery only) |
| UDP 30050 other `DAIKIN_UDP/aircon/*` paths | No reply |
| mDNS (`_daikin._tcp`, `_http._tcp`, `_https._tcp`) | Nothing advertised |

HTTP server header: `Heating WLAN/4.0.1.<commit>`.

## Conclusion

The BRP069A78 only exposes adapter metadata locally. It exposes **no heat-pump state and
no control**. All operational data goes through the Daikin cloud (Onecta API). This
matches community reports
([william-sy/Daikin-BRP069A62#13](https://github.com/william-sy/Daikin-BRP069A62/issues/13)).
Daikin's installer reference guide (4P624190-1A) also describes the cartridge only as a
gateway "to the Daikin Cloud … with the ONECTA app".

Consequences:

- The Miniserver cannot read or control the Altherma units through these cartridges.
- The Onecta cloud API cannot be called from the Miniserver either. It needs OAuth2
  (authorization-code flow with rotating refresh tokens over HTTPS), and Loxone cannot
  perform or persist that flow natively.
- A **native** Loxone integration therefore needs a local interface on the heat pump
  itself: Modbus through a Daikin HomeHub (EKRHH) or a DCOM gateway. See
  [`docs/PLAN.md`](../PLAN.md).
