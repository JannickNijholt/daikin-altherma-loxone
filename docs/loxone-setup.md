# Loxone setup: Daikin HomeHub over Modbus TCP

Template: [`loxone/templates/MB_Daikin_HomeHub_EKRHH.xml`](../loxone/templates/MB_Daikin_HomeHub_EKRHH.xml)
(generated by [`tools/build_loxone_template.py`](../tools/build_loxone_template.py)).
Register details: [reference/ekrhh-modbus-registers.md](reference/ekrhh-modbus-registers.md).

Requires Loxone Config 15 or newer, a Miniserver with Modbus TCP support, and one Daikin
HomeHub (EKRHH) per heat pump with **use case 3 (Modbus)** active.

## 1. Prepare each HomeHub

1. In the **ONECTA app**, activate use case 3 on the HomeHub, choose **Modbus TCP**, and
   note the **unit ID**.
2. Give the HomeHub a fixed IP (DHCP reservation), for example:
   - HomeHub "boven": `192.168.10.x1`
   - HomeHub "beneden": `192.168.10.x2`
3. Optional: verify it from a laptop before configuring Loxone (Phase 2 in the plan).

## 2. Import the template

1. Open Loxone Config and connect to the Miniserver.
2. In the periphery tree, select **Network Devices** and add a **Modbus Server**.
3. In the ribbon, open **Device Templates → Import Template** and select
   `MB_Daikin_HomeHub_EKRHH.xml`.
4. Create a Modbus Server from the template **twice**, once per heat pump:
   - Name: `WP Boven` / `WP Beneden`
   - Address: the HomeHub IP, port **502**
   - Unit ID / channel: the value from the ONECTA app (the template defaults to `1`)

## 3. What you get

Object names start with the Daikin register type and offset, so they map directly to the
Daikin documentation:

| Prefix | Meaning | Function code | Loxone object |
|---|---|---|---|
| `IRnn …` | Input register (live data) | FC 4 | Sensor, every 15 s (limits every 300 s) |
| `HRnn … (state)` | Holding register read-back | FC 3 | Sensor, every 60 s |
| `HRnn …` | Holding register command | FC 6 | Actuator, re-sent every 60 s |

Scaling is already applied: temperatures in °C, power in kW, flow in l/min. Holding-register
setpoints are **whole degrees**; Daikin defines them as Int16, so 20.5 °C is not possible
over Modbus.

### Replacing what Home Assistant does today

The HA device pages show this per heat pump:

| Today in HA (Onecta) | Loxone object | Notes |
|---|---|---|
| Room temperature, heating setpoint (20 / 18 °C) | `HR06 Room heating setpoint Main` | 12–30 °C, whole degrees |
| Room temperature, current (20.5 / 26.2 °C) | `IR50 Room temperature Main (remote controller)` | |
| Leaving water offset, heating (5 °C) | `HR54 WD LWT Main heating offset` | −10…10 °C, weather-dependent mode |
| Leaving water temperature, current (18 / 17 °C) | `IR40 Leaving water temperature PHE` | `IR41` = after backup heater |
| Automation "Warmtepomp uit of aan" | `HR04 Space heating/cooling ON/OFF` | 0/1 |
| Automation "Warmtepomp temperatuur wijziging" | `HR06` (and/or `HR54`) | |

Useful extras that HA didn't show: outdoor temperature (`IR44`), return water (`IR42`),
power consumption (`IR51`), flow (`IR49`), compressor/pump/defrost status, and error state
(`IR21`–`IR23`).

## 4. Things to know

- **Special values.** Raw `32765` means waiting for value, `32766` unavailable in this
  configuration, and `32767` unsupported. After scaling, temperature sensors show
  327.65–327.67 °C. Filter values above 300 °C in logic before using them.
- **Error code (`IR22`)** is two ASCII characters packed into one number:
  first char = `INT(v / 256)`, second char = `MOD(v; 256)`. Example: `21816` → 85, 56 →
  `U8`. Combine it with the sub code `IR23` (e.g. `U8-01`). Trigger a notification when
  `IR21` > 0.
- **Writes are change based.** The HomeHub only forwards a write when the register value
  changes, so the 60 s re-send is harmless and restores the state after a communication
  outage. A change made on the unit or in the Onecta app is **not** overwritten by the
  re-send as long as Loxone's value stays the same.
- **Read-back registers (`(state)`)** show the HomeHub's holding-register value, i.e. the
  last value written over Modbus. Whether they also follow changes made in the Onecta app
  or on the unit still has to be verified on the real installation (Phase 2).
- **Unused actuators.** An actuator only writes when you connect something to it. Leave
  registers you don't control (e.g. cooling, Add zone, thermostat inputs 59/61) unconnected
  or delete them.
- **Room setpoint (`HR06/HR07`)** only applies when the unit is controlled by room
  thermostat (`[C-07]=2`). Your HA setup controls room temperature, so this is expected to
  work. Confirm `[C-07]` on the unit.
- **DHW setpoint (`HR10`)** only applies with tank enabled, heat pump mode *Reheat only*,
  and setpoint mode *Fixed*. It can be ignored if the units have no tank.

## 5. Differences from the Loxone Library template

The Loxone Library ships "Daikin Heating & Cooling" (v2.0.2) for the same HomeHub. This
template was written from Daikin's register map instead and fixes these issues found in it:

| Register | Library template | This template |
|---|---|---|
| HR63 / HR64 (LWT Add setpoints) | both written to address 63 (HR64's address), so HR63 can't be written | addresses 62 / 63 |
| HR57 / HR58 power limits (Pow16) | no scaling: entering 5 kW writes 0.05 kW | ×100 scaling |
| IR50 room temperature | not divided by 100 (20.5 °C shows as 2050) | ÷100 |
| IR58–IR61 Add LWT limits | not divided by 100 | ÷100 |
| IR49 flow rate | labelled l/h | l/min (as specified by Daikin) |
| IR76–77 (DHW upper/lower), IR84–87 (room setpoint limits) | missing | included |
| Holding-register read-backs (FC 3) | only HR01, HR02, HR10 | all holding registers |

## 6. Regenerating the template

Edit the register list in `tools/build_loxone_template.py`, then run:

```bash
python3 tools/build_loxone_template.py
```

To verify the committed XML is valid and up to date:

```bash
python3 tools/build_loxone_template.py --check
```
